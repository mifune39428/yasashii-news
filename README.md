# やさしいニュース解説

政治・経済・国際のニュースを6時間ごとに集め、
「週刊こどもニュース」のように **そもそもの背景から** かみくだいて並べる静的サイト。

1本の記事につき用意するのは次の4つ。

- **ひとことで言うと** — 30〜50字。ここだけ読んでも意味が分かるようにする。
- **何があったの？** — いつ・だれが・何をしたか。
- **そもそも** — その組織は何をする所か、その制度はなぜあるのか、これまでの経緯。ここが肝。
- **わたしたちへの影響** — 暮らし・家計・仕事にどう関わるか。すぐ影響が無いなら正直にそう書く。

加えて、記事に出てきた難しい言葉を「ことば」として最大3つ、やさしい説明付きで持たせる。
画面上部の「📖 ことば辞典」は、いま表示している記事の「ことば」を集めたもの。
言葉を押すと、その言葉が出てくる記事だけに絞り込める。

## 構成

```
collect.py          RSS収集 → LLMで解説を生成・分類 → docs/articles.json
feeds.json          収集元の一覧（enabled で個別にON/OFF）
llm_providers.py    Gemini → Groq → Claude → OpenAI の順に落ちるフォールバック
docs/index.html     依存ライブラリなしの1ファイル。PWA対応（iPhoneのホーム画面に追加できる）
docs/articles.json  収集結果。GitHub Actions が差分をコミットする
更新.command        ダブルクリックで手動更新して push する
```

`.github/workflows/update.yml` が cron `0 */6 * * *`（日本時間 3/9/15/21時）で実行する。
手動で回すときは `更新.command` か、Actions の workflow_dispatch。

## 決めごと

- 載せるのは**やさしい見出し・独自の解説・出典名・原文リンクだけ**。原文の全訳はしない。
  原文の抜粋は `articles.json` にも残さない（`to_public()` が落としている）。
- 中立に書く。特定の政党・国・企業を持ち上げたりけなしたりしない、意見や「〜すべき」を書かない、
  と明示してLLMに渡している。それでも偏りは出るので、フッターにその旨を書いてある。
- 「そもそも」に書いてよいのは、一般に知られている仕組み・制度・経緯だけ。
  記事の細かい事実を、確認できないまま背景として足さない。
- スポーツ・芸能・料理・占い・広告は載せない。まずフィード取得時に `NOISE_RE` で粗く落とし、
  最終的な線引きはLLMの `relevant` 判定に任せる。
  事件・事故・災害は、政治や経済の動きにつながるものだけ載せる。
- 海外の記事は「🌐 日本語で読む」で Google 翻訳（translate.goog）を通したページを開く。
  URLの組み立てはブラウザ側だけで行い、収集時にGoogleへは問い合わせない。原文リンクも必ず併記する。
- 背景は薄いグレー（`--bg: #e9eaec`）で固定。ダークモードには追従しない。

## この題材ならではのハマりどころ

- **重複の除去がいちばんの肝。** 同じ会見・同じ発表を各社が書くので、素で回すと同じ話が並ぶ。
  語の重なりを見る `same_story()` だけでは
  「服の通販シーインが香港で上場へ」と「洋服通販のシーインが株式を売り出す計画」を取りこぼす。
  そこで解説を書いたあとに、見出しだけを並べてLLMに組を作らせる `drop_duplicate_stories()` を通す。
  実測で毎回1〜2件がここで落ちる。失敗したときは何も落とさない（重複が残るほうがマシ）。
- **一度「載せない」と決めた記事を覚えておく（`skipped`）。** そうしないと、
  守備範囲外の記事や重複の記事をRSSに残っている間ずっと解説し直して、解説の枠を食い潰す。
  記録は `docs/articles.json` の中に `{id, until}` で持ち、5日で忘れる（取り込み期間は2日）。
- **ジャンルの枠を先取りしないと国際と経済が埋まらない。** 政治のフィードは本数が多い。
  `GENRE_QUOTA` で24件のうち経済7・国際7を先に確保している。
- **総合フィードにはスポーツと料理が混ざる。** Yahoo!・時事・毎日・産経経済・東洋経済は
  `mixed: true` にして、LLMに渡す前に `NOISE_RE` で見出しを弾く。
  弾かずに渡すと、1回24件の解説枠を「ドミノ・ピザの新商品」で使うことになる。
- **無料枠のモデルが落ちると解説の質が目に見えて下がる。** Gemini の 3.6-flash が
  1日の上限に達すると 3.5-flash-lite まで落ちる。落ちた状態だと
  「制度が変わるニュース」まで守備範囲外と判定しがちだったので、
  `relevant` の指示を「false にするのはこれだけ」という書き方（否定の列挙）に直した。

## 上のメニューの出し入れと、お気に入り（`docs/ui.js`）

`docs/ui.js` は**6つのニュースサイトで同じものを使っている共通ファイル**。

- **下にスクロールすると上のメニュー（見出し＋絞り込み）が隠れ、一番上に戻すと出る。**
  隠すのは見出しの高さを過ぎてから、戻すのは一番上に着いたときで、しきい値を分けて
  境目でちらつかないようにしている。
- **記事カードの右上の ☆ を押すとお気に入りに入り、「★ お気に入り」タブでまとめて読み返せる。**
  タブは絞り込みの1段目、「すべて」のすぐ隣に入る（末尾に足すと横スクロールの外に出て気づかれない）。
  詳細ページ（`a.html`）にも「☆ お気に入り」が出る。

ページ側に足してあるのは次の4つだけ。

| 場所 | 中身 |
| --- | --- |
| `<head>` | `<script src="ui.js" data-site="yasashii-news"></script>`（**`defer` を付けない**） |
| `render()` | 記事カードを `<article data-id="${escapeHtml(item.id)}">` にする |
| `load()` | `all = window.NEWS_ITEMS = data.items || [];` |
| リンクの決め方 | `window.NEWS_LINK`（お気に入り一覧も同じリンク先を使うため） |

**気をつけること:**

- **`ui.js` は6サイトに同じ内容のコピーが置いてある。** 直すときは全部に配り直す。
  数え方は `md5 -q */docs/ui.js | sort -u | wc -l`（1なら揃っている）。
- **`data-site` を必ず入れる。** お気に入りは localStorage に持っていて、6サイトとも
  `mifune39428.github.io` の同じドメインにあるため、これが無いと互いのお気に入りが混ざる。
  URLから機械的に決めると、一覧（`/`）と詳細（`/a.html`）で別のキーになってしまう。
- **`<script>` に `defer` を付けない。** 付けると、詳細ページの `fetch` のほうが先に終わったときに
  `uiAttachDetail` がまだ無く、お気に入りボタンが付かないことがある。
  画面をいじる処理は `DOMContentLoaded` まで待つので、`<head>` に置いても表示は遅くならない。
- **お気に入りは記事のIDではなく記事そのものを写して持つ。** 一覧は30〜45日で入れ替わるので、
  IDだけ覚えても後から中身が引けない。入れ替わりで消えた記事は「掲載終了」と出し、
  解説ページではなく元記事へのリンクにする。
